# Phase 1d Security Audit: Upload, Injection, Secrets, CORS

Scope: read-only audit of backend upload handling, extraction/parsing surfaces, raw SQL, secret exposure, CORS, and dependency advisories on 2026-07-06. No functional code was changed.

| Item | File/Line | Status (Pass/Fail/Needs Review) | Notes |
|---|---|---|---|
| Upload endpoint auth | `routes/documents.js:324` | Pass | `POST /upload` is mounted with `requireAuth` before `upload.single("file")`; unauthenticated users cannot reach the upload handler. |
| Upload file type validation source | `routes/documents.js:59-72` | Fail | Multer `fileFilter` allows files solely by client-supplied `file.mimetype`. Allowed MIME strings are PDF, DOCX, and PPTX. There is no magic-byte/content sniffing before accepting or storing the file. |
| Upload extension handling | `routes/documents.js:51-55`, `utils/filenames.js:92-96` | Needs Review | Extension is derived from normalized `originalname` with `path.extname()` and a regex allowing `.[A-Za-z0-9]{1,10}`. Extension is used for the server temp filename and R2 object key suffix, but not as the primary allow/deny check. |

The known "filenames with parentheses break on Windows" class would be a functional path/interpreter issue here, not evidence of shell injection in this code path. |
| PPTX interpreter portability | `utils/extractionPipeline.js:515`, `utils/extractionPipeline.js:585-588` | Needs Review | The command is hard-coded to `python3`. On Windows this can fail if only `python`/`py` is installed. This is reliability, not injection. |
| PPTX extraction timeout | `utils/extractionPipeline.js:594-597` | Pass | PPTX extraction process is killed after 60 seconds. This limits runtime but not memory expansion inside the Python process before timeout. |
| PPTX parser behavior | `scripts/extract_pptx.py:11-12`, Python `pptx/opc/serialized.py:192-195` | Needs Review | `Presentation(filepath)` ultimately uses `zipfile.ZipFile(...).namelist()` and `z.read(name)` for every ZIP member, building an in-memory blob dictionary. | DOCX parser behavior | `utils/extractionPipeline.js:475-477`, `node_modules/mammoth/lib/unzip.js:10-14`, `node_modules/mammoth/lib/zipfile.js:8-24` | Needs Review | DOCX uses `mammoth.extractRawText({ path })`; Mammoth reads the whole compressed file via `fs.readFile`, loads it with JSZip, and inflates requested entries via `.async("uint8array")`.
